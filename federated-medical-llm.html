01. Project Overview

본 프로젝트는 이전에 수행한 LLM 기반 의료진 보조 처방 시스템을 확장한 연구입니다. 기존 연구가 단일 학습 환경에서 환자의 진단 정보를 바탕으로 처방 약물 리스트를 생성하는 데 초점을 맞췄다면, 본 프로젝트는 이를 여러 병원이 참여하는 분산 의료 데이터 환경으로 확장했습니다.

의료 데이터는 민감한 개인정보를 포함하기 때문에 병원 간 원본 데이터를 직접 공유하기 어렵습니다. 이에 본 프로젝트에서는 연합학습을 도입하여 각 병원이 로컬 데이터로 학습한 모델 업데이트만 서버에 전달하고, 서버는 FedAvg를 통해 글로벌 모델을 갱신하는 구조를 구성했습니다.

핵심은 의료 데이터를 직접 공유하지 않으면서도 병원 간 협력 학습을 가능하게 하고, LLM 기반 처방 약물 추천 성능을 분산 환경에서도 안정적으로 유지할 수 있는지 검증한 점입니다.

02. Motivation & Goal

Research Motivation

의료진 부족과 업무 과중 문제는 전 세계적으로 지속되고 있으며, 특히 응급·중환자 진료 환경에서는 신속하고 정확한 처방 결정이 매우 중요합니다. AI 기반 의료진 보조 시스템은 이러한 부담을 줄이는 데 도움을 줄 수 있습니다.

하지만 단일 병원 데이터만으로 학습한 모델은 처방 패턴이 특정 기관에 편향될 수 있습니다. 여러 병원의 데이터를 함께 활용하면 모델의 일반화 성능과 처방 다양성을 높일 수 있지만, 의료 데이터는 개인정보 보호 문제로 인해 직접 공유가 어렵습니다.

Research Goal

  • 환자 진단 정보를 기반으로 처방 약물 리스트를 생성하는 LLM 기반 시스템 확장
  • 병원 간 원본 데이터 공유 없이 협력 학습 가능한 연합학습 구조 구현
  • Flower 기반 Federated Learning 학습 환경 구성
  • Non-IID 의료 데이터 환경에서 연합학습 성능 안정성 평가
  • 차등 프라이버시를 적용하여 모델 업데이트 기반 개인정보 역추적 위험 완화
  • FFA-LoRA와 FlashAttention-2를 결합하여 LLM 학습의 통신·메모리 비용 절감

03. My Role

Research Planning

기존 LLM 기반 의료진 보조 처방 시스템의 한계를 분석하고, 이를 연합학습 기반 다기관 협력 학습 구조로 확장하는 연구 방향을 설계했습니다.

Data Preprocessing

MIMIC-IV 데이터를 다시 전처리하여 환자 정보, 진단 정보, 처방 약물 정보를 입원 단위로 병합하고, LLM 학습을 위한 Input-Response 형태로 변환했습니다.

Non-IID Dataset Split

연합학습 시뮬레이션을 위해 두 병원을 가정하고, 연령 분포 차이를 유도하여 A 병원과 B 병원의 Non-IID 데이터 환경을 구성했습니다.

Federated Learning Implementation

Flower 프레임워크를 기반으로 서버와 클라이언트 학습 구조를 구성하고, FedAvg 기반 글로벌 모델 업데이트 흐름을 실험했습니다.

LLM Fine-tuning & Optimization

Llama3.1-8B-Instruct 기반 모델을 연합학습 환경에서 파인튜닝하고, FlashAttention-2를 적용하여 LLM 학습의 메모리 사용량과 연산 병목을 줄였습니다.

Evaluation & Paper Writing

단일 학습과 연합학습 결과를 비교하고, 출력률·정확도·병원 간 성능 차이를 분석했습니다. 이후 실험 결과를 정리하여 논문 작성까지 수행했습니다.

본 프로젝트에서 저는 이전 의료 LLM 연구의 연장선 기획, MIMIC-IV 재전처리, Non-IID 데이터 분할, 연합학습 도입 및 파인튜닝, FlashAttention-2 적용, 실험 평가, 결과 분석, 논문 작성을 담당했습니다. LoRA/LoRA-FA 이론 및 적용 부분은 공동 연구자의 도움을 받았습니다.

04. Dataset & Non-IID Split

본 연구에서는 MIMIC-IV 데이터셋을 활용했습니다. 환자 ID와 입원 ID를 기준으로 환자 정보, 진단 정보, 처방 약물 데이터를 병합하고, 각 입원 단위의 진단 목록과 처방 약물 목록을 하나의 Input-Response 쌍으로 구성했습니다.

Step 1. Raw Data Selection patient, omr, diagnoses_icd, prescriptions 등 필요한 의료 테이블을 선택했습니다.
Step 2. Admission-based Merge subject_id와 hadm_id를 기준으로 환자 정보, 진단명, 처방 약물 리스트를 병합했습니다.
Step 3. Prompt Conversion 환자의 정보와 진단 목록을 input_text로 구성하고, 처방 약물 리스트를 response_text로 변환했습니다.
Step 4. Hospital Split 연합학습 환경을 위해 데이터를 A 병원과 B 병원으로 분할했습니다.
Step 5. Non-IID Setting 나이 분포를 기준으로 병원 간 데이터 이질성을 만들어 실제 임상 환경과 유사한 Non-IID 조건을 구성했습니다.

MIMIC-IV 원본 데이터와 LLM 학습용 Input-Response 데이터 구성 예시

A 병원과 B 병원의 연령 분포 차이를 통한 Non-IID 환경 구성

MIMIC-IV는 단일 진단과 특정 처방 약물을 1:1로 연결하는 명확한 키가 없기 때문에, 입원 단위의 모든 진단 목록과 모든 처방 약물 목록을 함께 묶어 학습 데이터로 구성했습니다. 이 구조적 특성은 정확도 평가가 낮게 측정될 수 있는 주요 원인입니다.

05. Method

LLM Backbone

Backbone 모델로는 Llama3.1-8B-Instruct를 사용했습니다. 해당 모델은 instruction 기반 입력에 적합하고, 의료 진단 정보를 바탕으로 처방 약물 리스트를 생성하는 텍스트 생성 태스크에 활용하기 적합하다고 판단했습니다.

FFA-LoRA

연합학습 환경에서 일반 LoRA를 적용할 경우, 각 클라이언트의 LoRA A/B 행렬을 FedAvg로 집계하는 과정에서 수학적 불일치가 발생할 수 있습니다. 이를 완화하기 위해 A 행렬을 고정하고 B 행렬만 학습하는 LoRA-FA 구조를 연합학습에 적용한 FFA-LoRA를 사용했습니다.

FlashAttention-2

Transformer의 Self-Attention 연산은 입력 길이가 길어질수록 메모리 사용량과 계산량이 크게 증가합니다. 본 프로젝트에서는 FlashAttention-2를 적용하여 LLM 학습 과정의 메모리 병목과 연산 비용을 줄였습니다.

Differential Privacy

연합학습은 원본 데이터를 공유하지 않는다는 장점이 있지만, 모델 업데이트를 통해 개인정보가 역추적될 가능성이 있습니다. 이를 완화하기 위해 Flower에서 제공하는 Central Differential Privacy 방식을 적용하여 서버 집계 단계에서 노이즈를 추가했습니다.

FFA-LoRA와 FlashAttention-2를 적용한 Llama3.1-8B-Instruct 기반 모델 구조

06. Federated Learning Setup

실험은 두 개의 병원 클라이언트와 하나의 중앙 서버가 존재하는 상황을 가정하여 구성했습니다. 각 클라이언트는 자신의 로컬 의료 데이터로 LLM을 학습하고, 서버는 클라이언트 가중치를 전달받아 FedAvg 방식으로 글로벌 모델을 업데이트했습니다.

Server

AMD Ryzen Threadripper PRO 5955WX 16-Cores CPU와 RTX 4080 24GB GPU 2개를 사용했습니다.

Client

각 클라이언트는 AMD Ryzen Threadripper PRO 3955WX 16-Cores CPU와 RTX 6000 Ada 48GB GPU 환경에서 학습했습니다.

Framework

Flower 프레임워크를 활용하여 연합학습 서버-클라이언트 구조를 구현했습니다.

Aggregation

각 클라이언트의 데이터 수를 반영한 FedAvg 방식으로 글로벌 모델 업데이트를 수행했습니다.

Round 1. Local Training 각 병원 클라이언트가 자신에게 할당된 의료 데이터로 로컬 모델을 학습합니다.
Round 2. Weight Upload 각 클라이언트는 원본 데이터가 아니라 학습된 모델 가중치만 서버로 전송합니다.
Round 3. Central DP 서버는 전달받은 업데이트에 차등 프라이버시 노이즈를 추가합니다.
Round 4. FedAvg Aggregation 서버는 클라이언트 업데이트를 가중 평균하여 글로벌 모델을 갱신합니다.
Round 5. Repeat 이 과정을 여러 라운드 반복하며 글로벌 모델의 성능을 평가합니다.

07. Evaluation Method

처방 약물 추천은 하나의 정답만 존재하는 단순 분류 문제가 아니기 때문에, 모델이 출력한 약물 리스트와 실제 처방 리스트의 일치 정도를 기준으로 정확도를 계산했습니다.

Accuracy = 각 샘플에서 출력된 약물 중 정답 약물과 일치한 약물 개수 / 전체 출력 약물 개수의 평균

또한 처방 약물 데이터는 진단-약물 간 1:1 연결이 불명확하기 때문에, 실제로 임상적으로 타당한 약물임에도 정답 리스트에 없으면 정확도에서 낮게 평가될 수 있습니다. 따라서 결과 해석에서는 단순 정확도뿐 아니라 출력률과 의료적 적합성 가능성도 함께 고려했습니다.

09. Conclusion

본 프로젝트는 LLM 기반 처방 약물 추천 시스템을 연합학습 환경으로 확장하여, 병원 간 원본 데이터 공유 없이도 협력 학습이 가능함을 확인했습니다. 단일 학습은 Full dataset 기준에서 더 높은 정확도를 보였지만, 분할된 A/B 병원 데이터 기준에서는 연합학습이 더 높은 평균 정확도를 기록했습니다.

또한 Non-IID 환경에서도 A 병원과 B 병원 간 성능 차이가 0.2%로 작게 유지되어, 연합학습이 데이터 분산 환경에서도 안정적인 성능을 보일 수 있음을 확인했습니다.

이 연구는 의료진의 판단을 대체하는 시스템이 아니라, 개인정보를 보호하면서 여러 병원의 의료 지식을 학습하고, 의료진이 최종 처방 결정을 내릴 때 참고할 수 있는 보조 도구로서의 가능성을 보여줍니다.
